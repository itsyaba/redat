# M3 — fast & interruptible (as built)

Measured on 2026-10-15 (typed command → first audio):
| | before | after |
|---|---|---|
| Claude first token | 6–10s (new `claude` process per turn) | ~1s |
| TTS first audio | ~4s (whole WAV) | ~0.8s (streaming MP3) |
| first audio total | ~15s | 2.8–3.7s |
Spoken turns add Addis STT (~2–2.5s) before that.

- **Persistent brain**: one `claude -p --input-format stream-json --include-partial-messages` process,
  started at daemon boot. Turns are written as JSON lines to stdin and serialized. If it dies, the next turn
  restarts it with `--resume <session>`.
- **Sentence streaming**: `Speaker` splits text deltas on ። ? ! ፧ ፨ and newlines, stops at the `EN:` line,
  starts a TTS request per sentence immediately (in parallel), and feeds MP3 into one `mpg123 -` process in
  order, so playback starts on the first chunk and sentences join without gaps.
- **Addis streaming TTS**: `POST /api/v1/voice/generations/stream`, protocol `mp3-frames-v1`
  (u32 BE length + MP3 frames, 0 terminator, then JSON billing). Found in the official `addisai`
  Python SDK, not documented on the web. Falls back to the whole-clip endpoint (MP3) if streaming fails.
- **Barge-in**: the hotkey during thinking/speaking cancels audio + pending TTS and listens. The
  interrupted turn finishes in the background without touching state/UI (generation counter).
- **Follow-up window**: after a spoken reply it listens 4s more (no notification); silence → idle quietly.
  `REDAT_FOLLOW_UP_MS=0` disables it. The hotkey during a quiet follow-up starts a normal listen.
- Voice: `REDAT_VOICE=am-yohanes-calm` (changed at the user's request; list: GET /api/v1/voice/voices).
